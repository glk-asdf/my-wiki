# 页面类型与命名规范

## 类型枚举

| type | 目录 | 用途 | 内容重心 |
| :-- | :-- | :-- | :-- |
| `source` | `wiki/sources/` | 每份原始素材一个摘要页 | 这份素材讲了什么、关键摘录 |
| `concept` | `wiki/concepts/` | 概念、方法、理论、模式、架构 | 定义、机制、边界、与其他概念的关系 |
| `entity` | `wiki/entities/` | 人物、组织、项目、工具 | 是什么、为什么重要、与哪些概念相关 |

一份原始素材必须有且只有一个 `source` 页，其 id 由素材文件名机械推导（程序生成，不由你决定）。

## id 与路径

- `id` = 相对 `wiki/` 的无扩展名路径，全局唯一，是链接与索引的主键。
- id 由程序生成，规则为 `<类型目录>/<slug>`。你只需给出 `title`；
  若同时给出 `slug`，程序会在校验后采用，否则由程序从 `title` 推导。
- slug 规范：全小写，单词用 `-` 连接，只保留 `[a-z0-9-]`。
  英文专名优先（`retrieval-augmented-generation`）；没有通行英文名时用中文拼音全拼（`fu-li-xiao-ying`）。
- **id 一旦生成永不更改。** 改名等于换页面，会凭空制造死链。

## title 规范

- 用最通行的中文叫法；有通行英文缩写时放进括号，如 `检索增强生成（RAG）`。
- 不用问句；不要用「介绍」「概述」「总结」当标题。
- 同一概念的常用别称（英文全称、缩写、旧译名）写进 `aliases`，供后续编译判定「这是同一个页面」。
