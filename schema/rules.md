# Wiki 维护规则

你在维护一个由「编译」产生的知识库。以下是硬约束，违反任何一条则整次输出视为无效。

## 一、页面粒度

- 一个概念一个页面，禁止把多个互相独立的概念塞进同一页。
- 正文超过 400 字，或包含 3 个以上互相独立的概念时，必须拆成多个页面并互相链接。
- 实体（人物、组织、项目、工具）与概念（方法、理论、模式、架构）严格分开，不得混写。

## 二、事实来源（最高优先级）

- 所有事实性陈述必须能在本次提供的原素材中找到依据。禁止补充原素材以外的常识、背景或外部知识。
- 每一条事实都必须在「出处」小节里有对应摘录。
- 摘录必须逐字复制自原素材，不得改写、翻译、缩写或补全。
- 不确定就宁可不写。空页面好过错误页面。

## 三、更新优先于新建

- 对每一个候选概念，**先在页面列表里找语义等价的页面**（包括别名、近义表述、不同译名）：
  找到即必须 update，禁止 create；确实找不到才允许 create。
- 「语义等价」看的是**讲的是不是同一件事**，不是名字像不像。
  「向量检索」与「向量检索技术」是同一个概念。
- 同一个概念在一次输出里只能出现一次，不要给出两个近义标题。
- update 时保持已有段落顺序与标题不动，新事实追加到语义最接近的那一节下面。
- **复利效应正体现在这里**：新素材的价值常常不是建新页，而是让旧页更准、更全。
  如果一次编译全是 create，说明你只是在堆摘要，没有在做知识管理。
- 禁止新增「补充说明」「其他」「杂记」「相关阅读」这类兜底小节。
- 不允许为凑内容而重写整篇。没有新事实时选择 noop。

## 四、链接

- 只能链接到页面列表中真实存在的 id，或本次新创建的页面。
- **禁止链接到 `raw/` 下的素材文件**（例如 `[[raw/foo.md]]`）。要引用素材时，链接它的摘要页
  `[[sources/xxx]]`——摘要页 id 见「可链接的页面 id」清单。
- 禁止凭空构造 id，禁止链接到原素材之外的外部资源。
- 反向链接区块由程序生成，禁止输出、禁止手写。

## 五、禁止事项

- 禁止输出「反向链接」区块或 AUTO-BACKLINKS 注释。
- 禁止创建标题为「列表」「杂记」「其他」「总结」「参考资料」的页面。
- 禁止输出 HTML 标签，禁止正文里出现表格。
- 禁止使用「本文」「本页」「如上所述」这类自指表述。
